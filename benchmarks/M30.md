# M30 filtered selective-search quality

The [raw 250,000-row run](m30/filter-selectivity-250k/run.json) measures the first
200 SIFT1M queries at `k=10` against the first 250,000 SIFT1M base vectors
(128 dimensions, squared Euclidean distance). The base prefix SHA-256 is
`fab6b3f6c68d8bca09c72b0ee84a8126b80aebc635765fb52c0ab3efbda51960`.
The probe builds a fresh `LocalStore` segmented namespace with 100-row requests,
the M24 acceptance loader's seal/consolidation maintenance schedule, and
`resident_filter = (cohort, one-percent)`. The resulting root has 20 runs,
1,482 blocks, and four tail objects. There is no block cache. The exact oracle
scans the loaded base vectors in f64 for each query and predicate, breaking
distance ties by ID. Recall is the fraction of exact top-10 IDs returned;
the fifth percentile is the tenth lowest per-query recall among 200 queries.
The short-result fraction counts queries returning fewer than ten neighbors.
The run used macOS (`Darwin arm64`) with Rust 1.98.1.

`serving` uses the M21 serving budget of 12 routed blocks, 8 range requests,
and 1 MiB of range bytes. `2x` and `4x` scale all three limits together.
The five equality predicates are deterministic ID assignments:

## Quality policy for this layout and budget

At the serving budget, no measured undeclared predicate, including the 50%
case, meets mean recall@10 >= 0.90 and P5 recall@10 >= 0.80. The declared
resident 1% predicate meets both exactly. Therefore the current post-filter
path has **no filtered quality guarantee** at the serving budget. A workload
requiring those gates for a sparse predicate needs the declared resident
predicate mechanism, subject to its index budget, or a measured filter-aware
routing path. Only the declared 1% case was measured as resident here. The
namespace supports one declared resident equality predicate.
Increasing all read limits 2x makes the 50% case pass, but no measured 10% or
rarer post-filter passes even at 4x. These observations do not establish a
threshold for other predicates or datasets. This probe measures quality and
result completeness, not latency or remote object-store traffic.

Reproduce with:

```sh
cargo run --offline --release --example m30_filter_probe -- /private/tmp/glider-m21-data/sift1m_base_250000.fvecs /private/tmp/glider-m21-data/sift1m_query.fvecs 250000 /private/tmp/glider-m30-filter-selectivity-250k > benchmarks/m30/filter-selectivity-250k/run.json
```

Use a fresh output directory for each run.
