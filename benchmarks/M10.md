# M10 bounded recovery and maintenance

The M8 stress input is 2,000 round-robin puts over 200 live IDs, 64 dimensions,
seed 42. The same generated vector fingerprint appears in both MinIO recovery
runs. A second input retains all 2,000 IDs to expose snapshot memory and write
cost. Measurements used Apple M4, 16 GiB RAM, loopback MinIO, three warm opens;
they are not remote-service latency claims.

| State | Open p95 | GETs / LIST pages | Peak client RSS | Visible objects |
|---|---:|---:|---:|---:|
| 2,000 separate log objects, 200 live IDs | 982 ms | 2,001 / 3 | 12.2 MiB | 2,001 |
| 20 batches of 100, 200 live IDs | 27.3 ms | 21 / 1 | 11.7 MiB | 21 |
| Same batches, compacted to one root | 6.18 ms | 2 / 1 | 11.4 MiB | 2 |
| 20 batches, 2,000 live IDs, one root | 17.5 ms | 2 / 1 | 17.8 MiB | 2 |
| 20 batches, 2,000 live IDs, 128 KiB chunks | 28.0 ms | 14 / 1 | 13.2 MiB | 14 |

The separate-object tail spent nearly all open time in replay. Batching changed
the request count while preserving the logical input and exact recovered map;
the payload read fell only from 1.60 to 1.52 MB. The chunked-root run measured
18.5 ms in GET calls and 1.69 ms in listing out of a 27.9 ms replay; the
remaining 7.8 ms includes manifest/chunk decoding and map construction. The
manifest is 1.5 KiB. A catalog replacement or decoder rewrite is not justified
at this size. This timing breakdown is specific to the chunked run.

At 2,000 live IDs, single-root compaction wrote 0.979 times the input mutation
payload. Chunked compaction wrote 0.980 times that
payload, and used 13 PUTs, 20 DELETEs and two LISTs. Its pre-cleanup maximum was
34 visible objects (21 old plus 13 new); cleanup left 14. Both layouts meet
the M8 additional-write and post-cleanup object budgets. The chunked layout
uses less peak memory and leaves room under the 64-GET recovery budget for the
M8 hard tail limit of 24 objects.

`MaintenanceLimits::m8()` is opt-in. It signals compaction at 16 tail objects
or 64 visible engine objects, and blocks the next mutation at 24 or 96. Batches
contain at most 100 operations. A blocked mutation publishes nothing and does
not poison the handle. An uncertain write or maintenance operation still
requires reopen; recovered counters come from the authoritative listing.
`compact()` or `compact_chunked(131072)` is the explicit response to the signal.
The policy is runtime configuration and must be set again after restart. The
128 KiB chunk choice was checked only for this M8 dataset; other layouts need
their own recovery budget check.
