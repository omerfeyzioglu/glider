# M22 segment and selective-read layout

Status: format design and range-read infrastructure in progress. No segmented
publication, cache, or larger-than-RAM acceptance is claimed.

## Decision tied to M23

The [M21 measurement](M21.md) found a 99.921 ms write-queue p95 at 10,000 rows
against 75 ms: four full snapshots uploaded 15,041,800 bytes while 80 changed
100-row batches uploaded 5,113,299 bytes. At 250,000 rows, routine full-base
rewrites violate the declared <=2 MiB/s upload gate by the structural
extrapolation in M21. The new layout must publish changed rows and allow a
query to fetch only selected vector blocks.

Use immutable physical segment objects targeted near 1 MiB, containing logical
blocks no larger than 128 KiB. The root manifest records each object's complete
payload length and, for each logical block, offset, length and SHA-256 of its
exact bytes. Blocks will carry a versioned record format and vector-partition
summary; each block is independently decodable and verifies before use. The
same `(immutable key, offset, length, digest)` identifies a RAM or NVMe cache
entry. Root/index metadata and in-flight block bytes count against the RAM
budget. An S3 range GET can transfer one selected block without fetching the
whole packed segment. This is a design target, not an on-disk format yet.

Small physical objects would let the current `get` validate an entire block,
but about eight times as many PUTs and keys would be needed for the same base
payload. One large indivisible object minimizes PUTs but makes each cold miss
transfer about 1 MiB. Packing keeps PUT count low while retaining a 128 KiB
read unit. Rewriting changed partition blocks was rejected in M21 because
scattered 100-row updates touch many blocks. No compression or ANN quality
benefit is assumed by this choice.

`ObjectStore::get_range` now takes key, payload offset, slice length and
expected complete payload length. S3 checks the complete envelope length and
rejects an oversized or short response. A range read does not verify the
whole-object `VTOBJ001` checksum: the caller must compare the selected bytes
against the block digest committed in a root before decoding or caching. Full
`get` still validates the complete envelope. Missing objects, length mismatch,
slice mismatch or digest mismatch must fail the dependent read; a cache miss
may refetch only within an explicit request/deadline budget. No write can be
acknowledged by cache state.

## Publication contract to implement

The new layout needs its own explicitly versioned metadata, root, block and
directory schemas. New metadata must make old readers reject this layout; an
existing namespace must be migrated through a validated fresh destination,
not reinterpreted in place. Keep one exclusive owner and one committer.
Successful immutable mutation-log publication remains the write acknowledgement
and query-visible boundary. A root covers a fixed sequence and carries retry
receipts/revision state plus references to immutable base and delta blocks.
Publish referenced blocks first, then one immutable root. Unpublished blocks
are never authoritative. A root error or uncertain response poisons writes and
maintenance; recovery chooses the highest complete valid root and replays
contiguous newer logs. Invalid selected roots or missing referenced blocks fail
closed. Deletes are tombstones and later sequence wins for an ID. Readers pin
one root and overlay newer acknowledged logs.

Reclamation follows durable root publication. A block or log cannot be deleted
while any selected root or pinned reader needs it; keys are never reused.
Bound the number of delta runs, metadata bytes, staging objects, deletion
backlog and replay tail. Spread any large merge across bounded steps fixed at
one input sequence, and reject new writes before resource bounds are exceeded
if maintenance falls behind. A faster worker alone is not a durability plan.

## Targeted infrastructure check

`python3 tools/test_s3.py --range-only` runs one disposable MinIO test. It
creates a 1,048,576-byte payload, reads a 131,072-byte interior slice with
one S3 GET, checks exact bytes, verifies missing-object and wrong-length
behavior, rejects invalid bounds before network I/O, and removes the container.
The local-store default also checks the slice and full-object length. These
tests establish the range API contract on MinIO; they do not measure query
latency, wire bytes, cache effects, block-digest enforcement by a reader, or
crash recovery of a future segment format.

M22 acceptance still requires the M21 250,000-row write/request/byte/recovery
gates, exact results, and MinIO publication/cleanup crash tests. M23 will
measure cold, NVMe-warm, RAM-hot and cache-pressure cases using this block
identity. M24 will compare selective results with the exact oracle and enforce
the stated quality and cost gates. No AWS test answers a question at this
stage.
