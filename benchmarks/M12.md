# M12 ANN feasibility decision

**Use exact serving for M8.** Production persisted IVF partitions are deferred
under M12's explicit exact-serving acceptance alternative.

Revision `25b878aeaa80c11149f659c4da1afafb9ae13703`, Rust 1.98.1 release,
Apple M4/macOS, in-memory ObjectStore. [Raw per-query evidence](m12/quality-gate.json).
Same M8 SplitMix64 inputs: 2,000 x 64, seed 42, 1,000 independent queries,
k=10, selected every 100 IDs, uniform and 16-cluster distributions.
32 partitions, eight training iterations. No remote latency is claimed.

The probe round-trips a version-1 candidate JSON partition containing sequence,
configuration, IDs, f32 vectors and metadata, then sizes each probed object.
It also sizes bundles of four partitions (eight objects total). Centers are
assumed resident, so modeled query GET costs are optimistic. Full probing
matches exact answers; the existing M8 independent oracle establishes input
and exact-neighbor correctness. Candidate layouts are not published engine
formats. Build plus existing cache serialization took 21.49 ms uniform and
12.62 ms clustered; these single samples are diagnostic, not latency gates.

| Sparse-filter probes | Uniform recall / short % | Clustered recall / short % | Partition GETs |
|---|---:|---:|---:|
| 8 fixed | 0.3676 / 94.7 | 0.4075 / 84.4 | 8 |
| 16 fixed | 0.6518 / 21.8 | 0.7124 / 50.5 | 16 |
| 24 fixed | 0.8725 / 0 | 0.9892 / 1.1 | 24 |
| 32 fixed | 1 / 0 | 1 / 0 | 32 |
| 8 then expand to fill k | 0.6044 / 0 | 0.9419 / 0 | up to 23 / 26 |

M8 requires recall >=0.90, short <5%, <=8 GETs and <=512 KiB. None of these
partition cases meets all four. Four-partition bundles use <=8 GETs but their
smallest observed transfer at eight probes is 572,088 bytes uniform and
729,501 bytes clustered, already above 524,288 bytes. Complete layouts occupy
about 1.50 MB. Every vector update invalidates this generation and requires
rebuilding or a new overlay protocol; M11's exact resident posting avoids this
additional write and recovery cost for the selected predicate.

A binary layout, fewer partitions or persistent filter-specific copies could
change the trade-off. They are not proved impossible. At this size resident
exact already meets the memory and latency budgets, and M11 selective exact
uses zero query GETs, so introducing a publication/GC protocol is unjustified.
The planned 10% approximate serving requests are therefore explicitly rejected;
the M13 workload sends those requests as exact after selecting that policy.

Failure/recovery checks: `cargo test --locked --test ivf` passed all 11 tests,
including lost publication acknowledgement, malformed derived cache, stale
cache reclamation, mutation invalidation and restart. The probe additionally
removes the cache, reopens authoritative data, rebuilds and checks exact/full
probe equality. This validates the retained implementation, not an unshipped
partition recovery protocol.

Reproduce: `cargo run --release --locked --example m12_quality_gate > target/m12.json`.
Remote benchmarks were skipped because the tested layouts fail deterministic
quality/request/byte gates before network latency can affect the decision.
