# M39 in-region AWS acceptance

## Per-seal layout on a free-tier instance

[Raw result](m39/aws-1m-per-seal/run.json): `tools/aws_acceptance.py --rows
1000000` at revision `f735f3a` (main with M33–M37 stage 3 plus this runner),
the M31 envelope against S3 Standard in eu-central-1 from an
`m7i-flex.large` (2 vCPU, 8 GiB; the only types this account's free plan
allows are burstable 2-vCPU instances). The instance built the revision,
read the SHA-verified SIFT files from the test prefix, ran load, serve and
verify, uploaded the result, deleted its namespace and terminated itself in
about 18 minutes; no run objects remained.

Correctness holds on S3 Standard. Query execution, not waiting (queue p95
21.7 ms), dominates query latency: routing scores the sketches of all
1,000,000 rows, which two burstable vCPUs cannot do within the gate. The
clustered view (M37) scores only the probed clusters' rows and is the next
in-region measurement. Open time and RSS are also higher than on MinIO; both
need attribution before conclusions.
