# Website

`site/` is static HTML, CSS and JavaScript with no build step. Preview it from
the repository root:

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory site
```

## Playground

"The life of a query" steps through write, cold query, repeated query,
`kill -9` and restart. `site/playground-model.mjs` holds the step state
machine; its latencies are p95 values from
[benchmarks/M39.md](../benchmarks/M39.md#current-main-on-s3), and
`site/playground.test.mjs` checks them against that table.

The three results come from `site/search-recording.mjs`, generated by the
engine test `website_search_matches_clustered_engine`
(`src/segmented/website_tests.rs`). It indexes 24 documentation summaries
(`tests/fixtures/site-search-input.json`, all-MiniLM-L6-v2 embeddings produced
by `tools/site_search_corpus.py`) through the clustered reader and asserts the
path the playground shows: the write is in the object store, the cold query
reads at most 8 ranges and matches exact search, the repeat reads nothing
remote, and a reopened database with an empty cache returns the same results.

```sh
# Regenerate after a reader change or after editing the corpus:
GLIDER_WEBSITE_OUTPUT=site/search-recording.mjs \
  cargo test --release --locked --lib website_search_matches_clustered_engine
# Checks run in CI:
cargo test --release --locked --lib website_search_matches_clustered_engine
node --test site/playground.test.mjs
python3 -m unittest discover -s tests -p 'test_site_setup.py'
```

Editing the corpus text requires new embeddings:

```sh
python3 -m venv /tmp/glider-site-embeddings-venv
/tmp/glider-site-embeddings-venv/bin/pip install sentence-transformers==5.1.1
/tmp/glider-site-embeddings-venv/bin/python tools/site_search_corpus.py
```

Check desktop and 375 px widths, keyboard use and reduced motion when editing
the playground.
