Open-source vector database · Rust

Vector search with S3 as the source of truth.

Glider is a single-node vector database. Every acknowledged write is durable in object storage; local RAM and SSD only make reads fast. When the server crashes, a restart takes over safely with no operator step.

Why Glider

The bucket is the database. Everything else is a cache.

Glider keeps no acknowledged state on local disk alone. That one rule makes crashes, cache loss and machine replacement ordinary events instead of incidents.

write batchconditional createimmutable log objectack

Durable on S3

Every acknowledged write is part of an immutable log object published with a conditional create. Nothing is overwritten in place, and a local disk never holds the only copy. The response is sent only after publication, so an acknowledged write survives any later crash.

  1. Wait out the old writer’s lease
  2. Fence it at the object store
  3. Replay the log tail

Crash-safe takeover

A paused former owner can never commit again. No operator step after a crash.

Retry-safe writes

Agents retry tool calls after timeouts. Every write carries a request ID, and resending it returns the original outcome instead of applying the write twice. Outcomes are retained for 128 commits.

Local SSD cache

A block cache fills in the background so warm queries need no remote reads. Losing it loses no acknowledged writes; latency and approximate recall recover as it warms.

250,000rows

Automatic clustering

At 250,000 rows the server builds a clustered view (centroids and cluster-contiguous postings) by itself, and rebuilds it as the collection grows. Unfiltered queries read at most 8 remote ranges and 1 MiB.

Architecture

Three paths, one bucket.

Writes become immutable log objects. Idle maintenance seals them into packs and a clustered view. Queries read a published snapshot through the local cache, and recovery fences the old writer at the store itself.

  • WriteA write batch becomes one immutable log object, created conditionally, before it is acknowledged.
  • SealIdle maintenance seals the log tail into packs of vector-local blocks with compact five-bit sketches.
  • ClusterRows are assigned to centroids, so a query reads only the nearest clusters’ blocks; small extents merge in the background.
  • FenceA renewed lease paces restarts, and permanent fence objects make a deposed writer’s next publication fail at the store.

Agent memory · MCP

Durable memory for agents that retry.

glider-mcp gives AI agents durable memory backed by Glider. A memory is acknowledged only after it is durable in Glider’s storage, and writes carry request IDs, so a retried tool call never stores it twice. New in 1.1

  • rememberStore text with optional tags; the same text in a scope replaces, not duplicates.
  • recallReturn the closest memories of a scope, with similarity scores.
  • forgetDelete one memory by ID, or every memory matching a scope or tags.
  • memory_countNumber of memories in a scope.

Text is embedded locally with fastembed (default BAAI/bge-small-en-v1.5, 384 dimensions; Python 3.10 or newer). recall uses exact search, so its cost grows with the number of memories.

Quickstart

Three commands to a nearest-neighbor query.

You need Docker and curl, no Rust toolchain. The image is multi-platform (linux/amd64, linux/arm64). This starts a 3-dimensional collection on a local directory, so its data is lost when the container stops; point it at S3 with the configuration variables to keep it.

The 1.1.0 image is the upcoming release; 1.0.1 is available today without exact queries, scans, batch reads or the operator filters. Docker Compose with MinIO and builds from source are in the README.

01 Start a server

docker run --rm -p 8080:8080 -e GLIDER_DIMENSIONS=3 \
  -e GLIDER_DATA_DIR=/var/lib/glider/data \
  ghcr.io/omerfeyzioglu/glider:1.1.0

02 Write two points

curl -sS localhost:8080/v1/write \
  -H 'content-type: application/json' \
  -d '{"upsert":[
    {"id":1,"vector":[0,0,0],"metadata":{"color":"red"}},
    {"id":2,"vector":[1,1,1]}]}'

03 Query

curl -sS localhost:8080/v1/query \
  -H 'content-type: application/json' \
  -d '{"vector":[1,1,0.9],"k":2,"include_metadata":true}'

The write returns a sequence and request_id; the query returns two hits ordered by distance.

04 Exact filtered query New in 1.1

curl -sS localhost:8080/v1/query \
  -H 'content-type: application/json' \
  -d '{"vector":[1,1,0.9],"k":2,"filter":{"color":"red"},"exact":true}'

New in 1.1 1.1.0

  • "exact": true on /v1/query: a filtered query returns every match, up to k.
  • Operator filters: $in, numeric ranges, $exists and nested $and/$or/$not.
  • POST /v1/points/get reads up to 1000 points by ID in one consistent read.
  • POST /v1/scan counts and pages through points that match a filter.

Exact queries and scans read every block of the collection: right for small collections, completeness-critical filters and evaluation. Limits are in the API reference.

Python client New in 1.1

A client that retries without writing twice.

Standard library only, Python 3.9 or newer. Each write carries a client-generated request ID, and a timed-out write is resolved by that ID before it is ever resent, so it is applied at most once.

Also: get_many, scan, count, upsert_many and delete_by_filter. See the client README.

Honest limits

A young engine, clear about its edges.

Glider is deliberately single-node today. These are the trade-offs to know before you deploy it.

  • Single node, single writerNo replication, sharding, read replicas or standby. Availability during a restart depends on the writer lease (default 10 s) and the open time.
  • Opening on S3 takes seconds3.15 s, and 4.00 s for a reopen, at 1,000,000 vectors; the target is 2 s.
  • Memory above target at 1MPeak engine RSS is 257.9 MiB on AWS (235.6 MiB on MinIO) against a 192 MiB target.
  • Filtered search is approximate by defaultMetadata values are strings. Only the declared resident predicate is exact by default; other filters may return fewer than k results unless you use exact: true, which scans every point.
  • TLS via a reverse proxyThe server speaks plain HTTP with an optional static bearer token; terminate TLS at a proxy or load balancer.
  • Fixed at creationDimension, metric, resident filter and routed keys are set when a collection is created. A point must fit in one 120 KiB storage block.
